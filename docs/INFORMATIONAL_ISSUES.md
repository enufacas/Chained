# Informational Issues Pattern

## Overview

**Informational issues** are issues that serve as reports, notifications, or status updates rather than actionable tasks. They are automatically marked with the `informational` label and are **not assigned to Copilot** for work.

## Purpose

Some automated workflows create issues to share information with the community:

- 📊 **Daily Evaluation Reports**: Agent performance summaries
- 📈 **System Status Updates**: Health checks and metrics
- 📝 **Automated Summaries**: Compiled data and insights
- 🔔 **Notifications**: Important system events

These issues are **view-only** and don't require Copilot intervention.

## Implementation

### Creating Informational Issues

When creating an automated issue that doesn't require action:

```bash
gh issue create \
  --title "📊 Daily Report" \
  --body "Report content here" \
  --label "informational"
```

**Key**: Include the `informational` label at creation time.

### How It Works

1. **Workflow creates issue** with `informational` label
2. **Assignment script checks labels** before assigning Copilot
3. **Script skips** issues with `informational` label
4. **Issue remains unassigned** - perfect for reports!

### Code Reference

**Label Creation** (`.github/workflows/agent-evaluator.yml`):
```bash
create_label_if_missing "informational" "d4c5f9" "Informational issue - no action required"
```

**Issue Creation** (`.github/workflows/agent-evaluator.yml`):
```python
result = subprocess.run(
    ['gh', 'issue', 'create', '--title', title, '--body', body, 
     '--label', 'agent-system,evaluation,informational'],
    capture_output=True,
    text=True
)
```

**Assignment Skip Logic** (`tools/assign-copilot-to-issue.sh`):
```bash
# Skip issues with informational label (no action required - just reports/status updates)
if echo "$issue_labels" | grep -q "informational"; then
  echo "⏭️  Skipping issue #$issue_number - has informational label (no action required)"
  already_assigned_count=$((already_assigned_count + 1))
  continue
fi
```

## Benefits

- ✅ **Prevents unnecessary assignments**: Copilot only works on actionable issues
- ✅ **Saves resources**: No wasted compute on reports
- ✅ **Clear distinction**: Easy to identify what needs action
- ✅ **Better organization**: Reports are clearly labeled
- ✅ **Avoids bugs**: No "null" agent name issues from forced assignments

### Other Use Cases

The `informational` label can be used for:

- 📊 **Performance Reports**: System metrics and benchmarks
- 🎯 **Goal Tracking**: Progress updates on milestones
- 📈 **Analytics**: Data visualizations and insights
- 🔍 **Audit Logs**: Important system events
- 📢 **Announcements**: General information sharing

## Best Practices

### When to Use

✅ **Use `informational` when**:
- Issue is a report or summary
- No action or decision is needed
- Purpose is to share information
- Generated by automated workflow

❌ **Don't use `informational` when**:
- Issue requires investigation
- Decision or approval is needed
- Changes need to be implemented
- Human intervention is required

### Label Combinations

Common patterns:

```
informational + evaluation       → Evaluation reports
informational + metrics          → Performance metrics
informational + announcement     → System announcements
informational + automated        → Auto-generated summaries
```

### Closing Informational Issues

Informational issues can be:

1. **Left open** as permanent records
2. **Auto-closed** after a retention period (e.g., 30 days)
3. **Manually closed** when no longer relevant

Consider adding an auto-close workflow for old informational issues to keep the issue list clean.
