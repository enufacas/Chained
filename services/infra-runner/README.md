# Infra Runner Service

**AI-Native Control Plane - Infrastructure Execution Layer**

This service provides deterministic infrastructure operations for AI-driven cloud deployments. It exposes a RESTful API for deploying static sites, dynamic services, and managing cloud resources on Google Cloud Platform.

## 🎯 Purpose

The Infra Runner service:
- Executes infrastructure plans generated by the AI Control Plane
- Deploys static sites to GCS buckets
- Deploys containerized services to Cloud Run
- Manages scaling, domains, and health checks
- Provides idempotent, deterministic operations
- Logs all infrastructure mutations to the event log

## 📡 API Endpoints

### 1. POST /deploy_static_site
Deploy a static website to GCS bucket with CDN and public access.

**Request Example:**
```json
{
  "app_id": "app-blog-2025",
  "bucket_name": "app-blog-2025-static-prod",
  "region": "us-central1",
  "files": [
    {
      "path": "index.html",
      "content": "<!DOCTYPE html><html>...</html>",
      "content_type": "text/html",
      "cache_control": "public, max-age=3600"
    }
  ],
  "public_access": true,
  "enable_cdn": true,
  "plan_hash": "sha256_abc123",
  "idempotency_key": "deploy_blog_20250106_120000"
}
```

**Response:**
```json
{
  "success": true,
  "operation_id": "op_20250106_120000_abc123",
  "resource_id": "app-blog-2025-static-prod",
  "status": "completed",
  "message": "Static site deployed successfully",
  "details": {
    "bucket_url": "https://storage.googleapis.com/app-blog-2025-static-prod",
    "public_url": "https://storage.googleapis.com/app-blog-2025-static-prod/index.html",
    "cdn_enabled": true,
    "files_uploaded": 1
  }
}
```

### 2. POST /deploy_dynamic_service
Deploy a containerized service to Google Cloud Run.

**Request Example:**
```json
{
  "app_id": "app-api-2025",
  "service_name": "app-api-2025-prod",
  "region": "us-central1",
  "image": "gcr.io/project-id/app-api:1.0.0",
  "port": 8080,
  "resources": {
    "cpu": "2",
    "memory": "4Gi"
  },
  "scaling": {
    "min_instances": 1,
    "max_instances": 10,
    "concurrency": 80,
    "cpu_throttling": true
  },
  "allow_unauthenticated": true,
  "ingress": "all",
  "plan_hash": "sha256_def456",
  "idempotency_key": "deploy_api_20250106_130000"
}
```

### 3. POST /scale_service
Adjust auto-scaling settings for an existing Cloud Run service.

### 4. POST /attach_domain
Attach a custom domain to a Cloud Run service with SSL.

### 5. POST /validate_plan
Validate a deployment plan without executing it (dry-run mode).

### 6. GET /check_service_health
Check the health status of a Cloud Run service.

**Request:**
```
GET /check_service_health?service_name=app-api-2025-prod&region=us-central1
```

**Response:**
```json
{
  "success": true,
  "service_name": "app-api-2025-prod",
  "status": "healthy",
  "details": {
    "service_url": "https://app-api-2025-prod-abc123-uc.a.run.app",
    "instances": {
      "min": 1,
      "max": 10,
      "current": 2
    },
    "health_check": {
      "status": "passing",
      "consecutive_failures": 0
    }
  }
}
```

### 7. GET /check_bucket_health
Check the health status of a GCS bucket.

## 🔧 GCP Configuration

### Environment Variables

**Required for Production:**
- `GCP_PROJECT_ID`: Your GCP project ID (required for real GCP operations)

**Optional:**
- `PORT`: Server port (default: 8080)
- `LOG_LEVEL`: Logging level (default: INFO)

### Authentication

The service uses **Application Default Credentials** (ADC) for GCP authentication:

**Local Development:**
```bash
# Login with your user account
gcloud auth application-default login

# Set project
gcloud config set project YOUR_PROJECT_ID

# Set environment variable
export GCP_PROJECT_ID=YOUR_PROJECT_ID
```

**Cloud Run Deployment:**
The service automatically uses the Cloud Run service account. Ensure the service account has:
- `roles/storage.admin` - For GCS bucket operations
- `roles/run.admin` - For Cloud Run service operations

### Stub Mode

If `GCP_PROJECT_ID` is not set, the service operates in **stub mode**:
- All endpoints return mock responses
- No actual GCP API calls are made
- Useful for development and testing without GCP credentials
- Health checks will indicate stub mode status

### Testing GCP Integration

```bash
# Run test suite
cd services/infra-runner
python test_gcp_client.py

# Expected output (stub mode):
# ✅ GCP client initialized
# ⚠️  GCP_PROJECT_ID not set, skipping bucket tests

# With GCP_PROJECT_ID set:
# ✅ Bucket existence check
# ✅ Service existence check
```

## 🚀 Running Locally

### Prerequisites
- Python 3.11+
- Virtual environment (recommended)

### Setup
```bash
# Create virtual environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Run the service
python main.py
```

## 🐳 Docker Deployment

### Build Image
```bash
docker build -t infra-runner:latest .
```

### Run Container
```bash
docker run -p 8080:8080 infra-runner:latest
```

### Deploy to Cloud Run
```bash
# Build and push to GCR
gcloud builds submit --tag gcr.io/PROJECT_ID/infra-runner:latest

# Deploy to Cloud Run
gcloud run deploy infra-runner \
  --image gcr.io/PROJECT_ID/infra-runner:latest \
  --platform managed \
  --region us-central1 \
  --allow-unauthenticated \
  --min-instances 1 \
  --max-instances 10 \
  --memory 512Mi \
  --cpu 1
```
